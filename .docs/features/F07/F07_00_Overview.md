# F07_00 借阅文档总览（Demo v1）

> 本版用于 Demo 对齐：先固化借阅申请到流程结束的主链路，并明确多审批人/多办理人的电子流设计口径。

## 1. Demo 范围

### 1.1 In Scope（本次 Demo 覆盖）

- 借阅申请（草稿/提交/撤回）
- 需求审核人审批（最小部门主管，同意/驳回/转审）
- 需求审批人审批（L3 主管，同意/驳回/转审）
- 借阅分单
- 借出审批（支持多人）
- 办理借出（支持多人）
- 使用人确认接收/下载
- 归还与结束
- 借阅单查询

### 1.2 Out of Scope（本次先占位）

- 库房出入库校验
- 跨法人借阅策略
- 实物物流寄送
- 续借申请、借阅记录管理、智能借阅的详细页面

## 2. 多审批/多办理电子流设计（已定稿）

### 2.1 核心模型

- **一单多明细**：一个借阅单可包含多条借阅明细。
- **明细级路由**：每条明细独立进入借出审批、办理、归还和结束。
- **主单聚合状态**：主单状态由明细状态聚合计算，不强制所有明细同节奏推进。

### 2.2 多人策略

- **审批策略**：`ALL`（全员同意）、`ANY`（任一同意）、`SEQ`（串行审批）。
- **办理策略**：`ASSIGN`（指定办理人）、`CLAIM`（候选人抢单）。
- **抄送策略**：除申请环节外，其他环节均可配置抄送。

## 3. 状态流（Demo 口径）

### 3.1 主单状态

`草稿` -> `待需求审核人审批` -> `待需求审批人审批` -> `待分单` -> `待办理` -> `待归还` -> `待确认接收` -> `已完成`

其他终态：`已撤销`、`已驳回`

### 3.2 明细状态

`待借出审批` -> `待办理借出` -> `待归还` -> `待确认接收` -> `已完成`

其他终态：`已驳回`、`已取消`

## 4. 规则摘要（Demo v1）

- **R-001**：原件借阅必须填写归还日期，且不超过当前日期后 1 个月。
- **R-002**：电子件/扫描件借阅必须填写下载有效期，且不超过当前日期后 90 天。
- **R-003**：同一档案原件借出后，`remaining_copies_quantity` 扣减；小于 1 时禁止再次借出原件。
- **R-004**：电子件/扫描件允许多人并发借阅，不受份数约束。
- **R-005**：逾期未归还自动发送催还通知（消息渠道先按邮件实现）。
